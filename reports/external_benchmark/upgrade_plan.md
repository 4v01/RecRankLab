# 第三版升级方案：先补强比较，再扩展模型与研究搜索

这是根据第二版真实运行和六组 GitHub 来源提出的**待验证方案**，不是已实现方法或已取得的性能承诺。第二版测试成绩已经被用于研究判断，因此后续不能把同一测试集的进一步提升包装为独立确认。

## P0：独立实现对齐与验证早停

1. 使用 RecBole 的 EASE／BPR／LightGCN 实现作独立对照，但必须接收我们保存的 fit frame、ID 映射和目录。禁止套用其默认 rating≥3、10-core、随机划分。先在验证集核对 Popularity 完全一致、EASE 数学解／评分在数值容差内一致、候选和 eligible-user 哈希一致。**未完成适配器重跑前，不引用外部高分作为差距估计。**
2. 将固定20/60/80轮改为预先声明的验证 checkpoint 选择，例如每5轮评估 NDCG@10、patience=3、最多80轮。对所有可迭代模型采用同样规则，记录评估本身的成本；最终使用选定 epoch 重新初始化并训练 train+val，再只测一次 test。绝不照搬 S3 的 test-recall stopping。
3. 单独记录模型种子和搜索种子；记录 trial 数、训练 epoch、optimizer steps、验证次数、总 wall time 和 CPU time。先以相同候选数比较，再附相同时间预算比较，不能把解析解 fit 和神经网络 epoch 当成同一计算单位。

验收：原有24项测试和数据审计继续通过；新测试必须证明 checkpoint/early-stop 从未看到 test、最终 refit 使用选定轮数、断点恢复不重复最终测试。保留固定轮数 v2 作为对照，不改写历史记录。

## P1：先做适合当前 CPU 的强经典基线

| 候选 | 机制与依据 | 建议预声明的四次验证拟合 | 主要风险／验收 |
|---|---|---|---|
| ItemKNN | EASE 的物品协同优势；S5 的经典基线 | cosine；(topK,shrink)=(100,10),(200,10),(500,10),(200,100) | 稀疏邻居不能泄露验证共现；所有历史评分继续用于候选屏蔽 |
| RP3β | 正例图上的多步物品协同与热门物品惩罚；S5 提供完整基线接口 | alpha∈{0.5,1.0} × beta∈{0.3,0.6}，固定 topK=200 | 分离“传播改善”与“热门度校正”；与 LightGCN 用同一图和 evaluator |
| SLIM ElasticNet／经许可核对的 ADMM 变体 | 学习稀疏物品系数；S5 中与 EASE 接近，是有意义的独立参照 | alpha∈{0.001,0.01} × l1_ratio∈{0.1,0.5} | 必须记录收敛状态与时间上限；未收敛标为失败，不挑最好迭代的测试值 |

先用 seed17 在**验证集**检查可运行性和时间，不能据测试成绩筛模型；正式比较再跑17/29/43。确定性模型的重复种子只核对复现。以上参数是下一轮的建议，不是已经冻结执行的实验；实施前需结合训练内数值尺度确认并提交配置。每模型最多四候选，失败／超时计入预算。

## P2：用排序重建目标替代继续堆显式 AutoRec

优先试原作者 S4 的 multinomial Multi-VAE／Multi-DAE，而不是照搬其 ML-20M 分数或 Recall 分母。输入仅训练正例，原有低评分历史仍供统一屏蔽；输出交给本项目 evaluator，保持原有 Recall 定义。

建议 Multi-VAE 先固定 latent=128，比较 hidden∈{200,600} × KL anneal cap∈{0.05,0.2} 四候选，采用 P0 验证早停。给出同时代 EASE、ItemKNN、SLIM 对照；记录输入 corruption、KL annealing、显存／内存与时间。明确这和 item AutoRec 同时改变了目标与架构，不称作纯损失函数因果消融。

若在当前双CPU环境无法按时间预算完成，就先保留为未完成项。SGL／XSimGCL 等图对比学习放在经典基线与验证早停之后；目前外部引用没有提供与我们完全一致协议下的可靠增益估计，不应凭论文名升级优先级。

## P3：把当前“有界参数搜索”升级为可证伪的研究记忆

当前 EASE 自优化与四点网格打平，**没有额外收益证据**。不能只更名为 Agent 或增加 LLM 调用就宣称升级。

- 保留 GIM 页面启发的“机制假设→受限参数提案→验证→成功/失败记忆”结构。每条记忆记录父提案、机制、代码/配置 SHA、数据版本、验证窗口、耗时、数值失败原因与指标差值。测试记录放在不向 proposer 暴露的存储边界。
- 对照固定网格、随机搜索、有界记忆搜索；每次均最多四个有效/失败 fit，并另给相同 wall-time 预算。搜索随机种子独立于模型种子，至少三个搜索轨迹；不能用确定性 EASE 的三个重复模型种子冒充搜索策略的不确定性。
- 先支持有类型的 YAML 参数与预审机制模板，例如正则、邻居截断、训练内热门度校正；不直接执行任意生成代码。任何新模板需先过语法、数值、未来信息依赖和候选政策检查。
- 训练内增加两个滚动验证窗口，检验某条记忆是否跨窗口有效；时间与数据成本必须计入预算。若只有单窗口、少数候选，就只报告局部搜索表现。
- 将“同预算下验证改善、独立确认改善、失败率、总成本”作为系统指标。记忆搜索若仍无优势，应保留网格／随机搜索，不预设其必须成功。

这仍是推荐研究中的有限方法借鉴，不声称复现 CogAlpha/XALPHA 的金融数据、代理架构或论文结论。LLM reranking 继续低于这些工作优先级。

## P4：独立确认和规模化前置条件

保持 ML-1M 原协议作为连续性主表；可另外预声明全球时间切分作敏感性分析，单独报告暖用户比例和冷启动剔除，不能替换主表来追求更高分。

更强泛化证据需要在升级配置冻结后评估一个此前未被研究反馈使用的数据设置。ML-20M 是候选，但当前实现会缓存全用户×物品稠密分数，EASE 又需要 O(items²) 逆矩阵；在8GiB环境不应直接承诺跑全规模。应先实现批量评分、稀疏历史和分块候选评估，评估峰值内存，再决定可行的独立数据与方法。若只能做同一数据上的新划分，必须承认它仍非完全独立数据集。

最终交付继续要求：真实逐次记录、固定 source SHA、完整配置/数据指纹/种子、统一候选哈希、原始失败记录、配对区间、预算和资源表。没有重跑的外部成绩只保留在外部报告层，不混入本地主结果。
